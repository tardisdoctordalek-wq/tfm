## 1. 무엇을 만들었나

딸 **나율이**가 주인공인 2D 액션 플랫포머 (슈퍼마리오 스타일).

- 외부 라이브러리 **0개**, 이미지·사운드 파일 **0개**
- 캐릭터·적·타일 전부 코드 안의 도트(픽셀) 데이터
- 효과음과 배경음은 WebAudio 로 직접 합성
- 브라우저만 있으면 실행. PC 키보드 / 휴대폰 터치 모두 지원

## 3. 도트 제작 방식 (가장 중요한 부분)

손으로 글자를 하나씩 찍는 방식은 품질 한계가 뚜렷해서, **코드로 그린 뒤 도트로
떨어뜨리는 생성기**를 만들어 쓰고 있습니다.

```bash
node tools/nayul-gen.js --size=96          # 옆모습 (게임 플레이용 원본)
node tools/nayul-gen.js --size=96 --front  # 정면 (메인 화면용)
node tools/nayul-gen.js --size=28 --ss=8 --code   # 게임에 넣을 크기
```

동작 순서
1. 96칸 좌표계에 캐릭터를 그림 (`tools/nayul-gen.js` 안의 `DRAW`)
2. 3~8배 크기로 렌더링한 뒤 목표 크기로 축소
3. 팔레트에서 가장 가까운 색으로 스냅(양자화)
4. 바깥 테두리를 어두운 색으로 덮어 실루엣을 또렷하게

이 방식의 이점: **한 벌의 그림에서 96 / 32 / 28 세 크기가 동시에** 나옵니다.
크기별로 따로 그리면 얼굴이 서로 달라지는데, 그 문제가 생기지 않습니다.

### 크기 규격

| 그림 | 도트 | 화면(배율 2) | 쓰이는 곳 |
|---|---|---|---|
| 나율이 작은 상태 | 28 × 28 | 56 × 56 | 게임 플레이 |
| 나율이 큰 상태 | 32 × 32 | 64 × 64 | 하트 먹었을 때 |
| 나율이 정면 | 96 × 96 | 192 × 192 | 메인 화면 |
| 밤톨이 | 16 × 16 | 32 × 32 | |
| 날개새 | 20 × 16 | 40 × 32 | |
| 코인 · 하트 | 12 × 12 | 24 × 24 | |
| 타일 | 16 × 16 | 32 × 32 | |

**모든 그림은 배율 2로 그립니다.** 어떤 것만 1배로 그리면 그 그림의 도트만 작아져서
화면이 따로 놉니다. (실제로 초기에 타일만 1배라 스타일이 깨졌습니다.)

## 5. 찾아서 고친 버그 (전부 측정으로 확인)

품질 불만의 상당수가 그림 문제가 아니라 **코드 버그**였습니다.

### 5-1. 평지를 걷는데 점프 자세가 섞임 ← "팔다리가 파닥거린다"의 정체
상태를 프레임마다 찍어 보니 `run → jump → run → jump` 로 **매 프레임 교대**.
발이 바닥 높이에 딱 맞은 프레임에서는 아래 충돌 검사가 아무것도 못 찾아
"공중"으로 판정. 점프 자세는 팔을 든 그림이라 팔이 계속 올라갔다 내려옴.
→ 발밑 한 칸을 확인하는 보정 추가. **측정: 걷기 60프레임 전부 `run`, 점프 0회**

### 5-2. 가만히 서 있는데 몸이 떨림
y 좌표가 `392 ↔ 392.55` 로 매 프레임 진동. 중력으로 0.55px 가라앉은 뒤
되돌리지 못한 것. 화면에 그릴 때 반올림되어 1픽셀 떨림.
→ 발밑 보정에서 바닥에 딱 붙이고 낙하 속도 0. **측정: 60프레임 y=392 고정**

### 5-3. 벽에 대고 방향키를 누르면 급속히 떨림
충돌이 끝 픽셀을 계산할 때 `-1` 을 써서 벽·바닥에 1px 틈이 생김.
매 프레임 조금씩 파고들었다 밀려남.
→ `-1` 대신 `-0.01`. 더불어 걷기 애니메이션 기준을 속도가 아니라
**실제로 움직인 거리**로 변경. **측정: 벽에 미는 동안 이동량 0, 그림 교체 0회**

### 5-4. 축소하면 그림 전체가 지글거림
96칸 좌표계에서 다리를 1~2칸 움직였는데 28도트에서는 도트 경계에 안 맞아,
축소할 때 머리까지 다시 계산됨.
→ 움직임을 도트 한 칸의 정수배로만. **측정: 프레임 간 변화 113칸 → 12칸,
바뀌는 줄도 발 부분(24~27줄)만**

### 5-5. 1스테이지에 빠져나올 수 없는 구덩이
피라미드 사이 한 칸 구멍의 깊이가 128px 인데 최대 점프 높이는 114px.
자동 플레이 봇이 여기서 계속 갇혀 시간 초과로 죽었음.
→ 꼭대기를 평평하게 메움. 세 스테이지 전체를 스캔해 같은 구멍이 없음을 확인

### 5-6. 그 밖
- 빠르게 떨어질 때 적 밟기 판정이 새던 문제 (직전 프레임 발 위치 기준으로 변경)
- 가시 타일이 흰 점으로 깨져 나오던 문제
- 배경 언덕이 잔디와 같은 초록이라 지면이 묻히던 문제
- lint 도구가 보조 재질 톤(5~8)을 모르던 문제

## 6. 확인된 것 / 아직 확인 못 한 것

확인됨
- 자바스크립트 오류 0건 (타이틀 → 플레이 → 일시정지 → 사망 → 재시작)
- 세 스테이지 모두 빠져나올 수 없는 한 칸 구멍 없음
- 걷기·정지·벽 밀기·돌아서기 상태 전환이 프레임 단위로 안정적
- PNG → 도트 코드 왕복 변환이 원본과 정확히 일치

아직 확인 못 함
- **사람이 3스테이지를 끝까지 깰 수 있는지** (자동 봇은 시간 초과로 중단)
- 실제 기기(딸 태블릿/폰)에서의 터치 조작감
- 난이도가 2~3세 아이에게 적절한지

## 7. 남은 일 (다음에 할 것)

우선순위 순

1. **목 모양** — 옆모습에서 턱과 목 이음새가 어색함. 턱선을 넣어 다시 그려 봤으나
   "이전 게 더 귀엽다"는 피드백으로 되돌림. 얼굴은 그대로 두고 목만 손보거나,
   옷깃을 한 칸 올려 목을 덜 보이게 하는 방법이 남아 있음
2. **발 미끄러짐(스키 타기)** — 걷기가 4프레임이라 발이 미끄러져 보임.
   8~10프레임으로 늘리면서 "발을 들어 앞으로 뻗는" 중간 동작을 넣으면 해결
3. **3스테이지 클리어 가능성 검증** — 사람이 직접 플레이하거나 봇 개선
4. **난이도 조절** — `js/config.js` 의 `PHYS` 로 점프 높이·중력·속도 조절
5. 메인 화면 정면 나율이에 걷기·손 흔들기 동작 추가
6. 캐릭터를 화면에서 더 크게 보이게 하려면 타일을 32→48px 로 키우는 방법이 있으나
   레벨 화면 구성을 다시 잡아야 함

```bash
node tools/nayul-gen.js --size=96 --code    # 주인공 도트 뽑기
```

## 9. 자주 고치는 것

| 고치고 싶은 것 | 위치 |
|---|---|
| 이름 | `js/config.js` 의 `PLAYER_NAME` |

## 10. 알아 둘 것

- 네이버 블로그·레딧은 이 작업 환경에서 **차단**되어 링크로는 못 엽니다.
  참고 자료는 **HTML 파일이나 캡처로 전달**해야 읽을 수 있습니다.
- 사진 원본은 저장소에 넣지 않았습니다. 색을 뽑는 데만 썼습니다.
- 에이전트를 3개로 나눠 병렬 작업을 시도했으나 세션 사용량 한도로 전부 실패했습니다.
  분할 자체는 유효했고(파일이 안 겹치게 나눠 둠) 한도가 풀리면 재시도 가능합니다.
