## 3. 도트 제작 방식 (가장 중요한 부분)

손으로 글자를 하나씩 찍는 방식은 품질 한계가 뚜렷해서, **코드로 그린 뒤 도트로
떨어뜨리는 생성기**를 만들어 쓰고 있습니다.

```bash
node tools/nayul-gen.js --size=96          # 옆모습 (게임 플레이용 원본)
node tools/nayul-gen.js --size=96 --front  # 정면 (메인 화면용)
node tools/nayul-gen.js --size=28 --ss=8 --code   # 게임에 넣을 크기
```

동작 순서
1. 96칸 좌표계에 캐릭터를 그림 (`tools/nayul-gen.js` 안의 `DRAW`)
2. 3~8배 크기로 렌더링한 뒤 목표 크기로 축소
3. 팔레트에서 가장 가까운 색으로 스냅(양자화)
4. 바깥 테두리를 어두운 색으로 덮어 실루엣을 또렷하게

이 방식의 이점: **한 벌의 그림에서 96 / 32 / 28 세 크기가 동시에** 나옵니다.
크기별로 따로 그리면 얼굴이 서로 달라지는데, 그 문제가 생기지 않습니다.

### 크기 규격

| 그림 | 도트 | 화면(배율 2) | 쓰이는 곳 |
|---|---|---|---|
| 나율이 작은 상태 | 28 × 28 | 56 × 56 | 게임 플레이 |
| 나율이 큰 상태 | 32 × 32 | 64 × 64 | 하트 먹었을 때 |
| 나율이 정면 | 96 × 96 | 192 × 192 | 메인 화면 |
| 밤톨이 | 16 × 16 | 32 × 32 | |
| 날개새 | 20 × 16 | 40 × 32 | |
| 코인 · 하트 | 12 × 12 | 24 × 24 | |
| 타일 | 16 × 16 | 32 × 32 | |

**모든 그림은 배율 2로 그립니다.** 어떤 것만 1배로 그리면 그 그림의 도트만 작아져서
화면이 따로 놉니다. (실제로 초기에 타일만 1배라 스타일이 깨졌습니다.)

## 5. 찾아서 고친 버그 (전부 측정으로 확인)

품질 불만의 상당수가 그림 문제가 아니라 **코드 버그**였습니다.

### 5-1. 평지를 걷는데 점프 자세가 섞임 ← "팔다리가 파닥거린다"의 정체
상태를 프레임마다 찍어 보니 `run → jump → run → jump` 로 **매 프레임 교대**.
발이 바닥 높이에 딱 맞은 프레임에서는 아래 충돌 검사가 아무것도 못 찾아
"공중"으로 판정. 점프 자세는 팔을 든 그림이라 팔이 계속 올라갔다 내려옴.
→ 발밑 한 칸을 확인하는 보정 추가. **측정: 걷기 60프레임 전부 `run`, 점프 0회**

### 5-2. 가만히 서 있는데 몸이 떨림
y 좌표가 `392 ↔ 392.55` 로 매 프레임 진동. 중력으로 0.55px 가라앉은 뒤
되돌리지 못한 것. 화면에 그릴 때 반올림되어 1픽셀 떨림.
→ 발밑 보정에서 바닥에 딱 붙이고 낙하 속도 0. **측정: 60프레임 y=392 고정**

### 5-3. 벽에 대고 방향키를 누르면 급속히 떨림
충돌이 끝 픽셀을 계산할 때 `-1` 을 써서 벽·바닥에 1px 틈이 생김.
매 프레임 조금씩 파고들었다 밀려남.
→ `-1` 대신 `-0.01`. 더불어 걷기 애니메이션 기준을 속도가 아니라
**실제로 움직인 거리**로 변경. **측정: 벽에 미는 동안 이동량 0, 그림 교체 0회**

### 5-4. 축소하면 그림 전체가 지글거림
96칸 좌표계에서 다리를 1~2칸 움직였는데 28도트에서는 도트 경계에 안 맞아,
축소할 때 머리까지 다시 계산됨.
→ 움직임을 도트 한 칸의 정수배로만. **측정: 프레임 간 변화 113칸 → 12칸,
바뀌는 줄도 발 부분(24~27줄)만**

### 5-5. 1스테이지에 빠져나올 수 없는 구덩이
피라미드 사이 한 칸 구멍의 깊이가 128px 인데 최대 점프 높이는 114px.
자동 플레이 봇이 여기서 계속 갇혀 시간 초과로 죽었음.
→ 꼭대기를 평평하게 메움. 세 스테이지 전체를 스캔해 같은 구멍이 없음을 확인

### 5-6. 그 밖
- 빠르게 떨어질 때 적 밟기 판정이 새던 문제 (직전 프레임 발 위치 기준으로 변경)
- 가시 타일이 흰 점으로 깨져 나오던 문제
- 배경 언덕이 잔디와 같은 초록이라 지면이 묻히던 문제
- lint 도구가 보조 재질 톤(5~8)을 모르던 문제

## 5-A. 이야기와 파워업 시스템 (2026-09-15)

### 왜 만들었나
게임에 이야기가 없었습니다. 들판 → 동굴 → 하늘로 이어지지만 왜 가는지가 없고,
클리어 동기가 "깃발 만지기"뿐이었습니다. 아빠를 찾아가는 이야기를 넣고,
스테이지마다 다른 기믹(너구리마리오식 변신)을 붙였습니다.

### 어떻게 만들었나 — 기존 구조를 최대한 그대로 씀
코드를 먼저 읽고, **새로 만들지 않아도 되는 것**을 골라냈습니다.

| 필요한 것 | 이미 있던 것 | 한 일 |
|---|---|---|
| 스테이지 테마 | `THEME` 객체 (들판/동굴/하늘) | `house` 한 벌 추가. `theme` 을 쓰는 곳이 3군데뿐이라 확장이 쉬웠음 |
| 파워업 | `!` 블록 → 하트 → `setBig(true)` 2단 구조 | 그 위에 3단째를 얹음 (파워 → 큰 → 작은) |
| 적 | `Walker` / `Flyer` 두 클래스 | 움직임은 그대로 두고 **도트만** 테마별로 갈아 끼움 |
| 청소기 든 나율이 | — | **주인공 도트는 안 건드림.** 청소기를 위에 덧그림 |

마지막 항목이 중요합니다. `js/sprites/player.js` 는 1904줄짜리 생성물이라,
물건을 쥔 그림을 새로 뽑으면 걷기 4프레임 × 작은/큰 상태를 전부 다시 만들어야
합니다. 물건만 따로 그려서 손 위치에 얹으면 자동차·침도 같은 방식으로 붙습니다.

### 새로 생긴 것

- `*` 블록 — 그 스테이지의 파워업이 나옵니다 (`js/levels.js` 의 `power:` 가 정함)
- 액션 버튼 — 키보드 `C` / `F`, 터치 버튼 1개. 파워를 얻으면 버튼 글자가
  "액션" → "청소기" 로 바뀝니다 (아이가 뭘 누르는지 알아보게)
- 집 테마 — 마룻바닥 · 벽 타일 · 서랍장 · 레고 조각(가시 대신) · 벽시계 · 화분,
  배경에 벽지 / 창문 / 액자 / 가구 실루엣
- 집 테마 적 — **먼지뭉치**(걷는 적) · **나방**(나는 적)
- 골이 깃발 대신 **현관문** ("아빠한테 가자!")

### 청소기에서 조심한 것

1. **빨려 오는 적이 나를 죽이는 문제** — 적을 끌어당기면 결국 내 몸에 닿습니다.
   그대로 두면 빨아들이다가 자기가 맞아 죽습니다.
   → 빨리는 중인 적(`e.sucked`)은 충돌 판정에서 건너뜁니다.
2. **끌어당긴 위치가 되돌아가는 문제** — 흡입은 `Player.update` 안에서 일어나고,
   그 다음에 각 적의 `update` 가 돌면서 제 갈 길로 움직입니다.
   → `sucked` 인 적은 자기 `update` 를 건너뜁니다.
3. **버튼을 떼면 적이 얼어붙는 문제** — 표시를 안 풀면 그 자리에 멈춰 있습니다.
   → 버튼을 뗀 프레임에 전부 풀어 줍니다. 파워를 잃을 때·죽을 때도 풉니다.
4. **모터 소리가 지직거리는 문제** — 프레임마다 소리를 새로 만들면 끊깁니다.
   → 오실레이터 한 개를 만들어 켜고 끕니다 (`Sound.vacuumOn/Off`).

### 눈으로 보고 고친 것 (캡처로 확인)

- **바닥이 마루가 아니라 벽돌 격자로 보임** — 타일마다 세로 테두리를 넣고
  판자를 4도트로 했더니 격자가 됐습니다. 세로선을 빼고 판자를 8도트로 키우고
  이음매를 엇갈리게 두니 마루로 읽힙니다.
- **배경 가구와 밟을 수 있는 선반이 구분이 안 됨** — 둘 다 나무색이라 아이가
  어디를 밟아야 하는지 알 수 없었습니다. 배경 가구를 반투명(0.5)으로 깔고
  채도를 낮췄으며, 선반 색을 더 밝게 올렸습니다.
- **`=` 블록이 욕실 타일처럼 보임** — 집 가구 색(연한 민트)으로 바꿨습니다.

### 새로 만든 검사 도구

```bash
node tools/check-level.js   # 빠져나올 수 없는 곳 / 골 도달 가능성 / 파워 블록 존재
node tools/playtest.js      # 실제로 띄워서 동작 측정 + 화면 캡처
```

`check-level.js` 는 **점프 높이를 적어 두지 않고 `PHYS` 에서 계산**합니다.
숫자를 적어 두면 물리값을 고쳤을 때 거짓말을 하게 됩니다.
계산 결과: 최대 점프 높이 **110.5px (3타일)**, 체공 41프레임,
걷기로 건널 수 있는 최대 폭 **135px (4타일)**.
(작업기록 5-5 의 실측 114px 과 거의 같습니다.)

`playtest.js` 로 측정해 통과한 것 — **10건 전부 통과, 자바스크립트 오류 0건**

| 확인한 것 | 결과 |
|---|---|
| 점프로 `*` 블록을 치면 청소기가 나옴 | 블록 `*`→`X`, 아이템 1개 |
| 먹으면 `power='vacuum'`, `big=true` | 통과 (터치 버튼 글자도 "청소기"로) |
| 청소기로 적을 없애고 점수가 오름 | 적 1→0마리, 점수 500→700 |
| **빨아들이는 동안 다치지 않음** | 목숨 3→3, 피격 0회 |
| 맞으면 3단으로 내려감 | 파워(h=64) → 큰(h=64, power=null) → 작은(h=56) → 죽음 |
| 2·3스테이지 회귀 | 그대로 동작 |

## 6. 확인된 것 / 아직 확인 못 한 것

확인됨

## 7. 남은 일 (다음에 할 것)

우선순위 순

0. **2스테이지 길거리 + 자동차, 3스테이지 한방병원 + 침 던지기**
   `js/powers.js` 에 항목을 추가하고, `js/sprites/tiles.js` 의 `THEME` 에
   테마를 한 벌씩 넣고, `js/levels.js` 의 `power:` 를 채우면 됩니다.
   1스테이지에서 다 만들어 둔 뼈대를 그대로 씁니다.
0-1. **아빠 도트와 인트로 컷신** — `tools/nayul-gen.js` 에 아빠 그리기를 추가하고,
   타이틀 뒤에 "아빠가 출근한다" 컷신, 3스테이지 골에서 아빠를 만나는 장면
1. **목 모양** — 옆모습에서 턱과 목 이음새가 어색함. 턱선을 넣어 다시 그려 봤으나
   "이전 게 더 귀엽다"는 피드백으로 되돌림. 얼굴은 그대로 두고 목만 손보거나,
   옷깃을 한 칸 올려 목을 덜 보이게 하는 방법이 남아 있음
2. **발 미끄러짐(스키 타기)** — 걷기가 4프레임이라 발이 미끄러져 보임.
   8~10프레임으로 늘리면서 "발을 들어 앞으로 뻗는" 중간 동작을 넣으면 해결
3. **3스테이지 클리어 가능성 검증** — 사람이 직접 플레이하거나 봇 개선
4. **난이도 조절** — `js/config.js` 의 `PHYS` 로 점프 높이·중력·속도 조절
5. 메인 화면 정면 나율이에 걷기·손 흔들기 동작 추가
6. 캐릭터를 화면에서 더 크게 보이게 하려면 타일을 32→48px 로 키우는 방법이 있으나
   레벨 화면 구성을 다시 잡아야 함

## 8. 자주 쓰는 명령어

```bash
node tools/nayul-gen.js --size=96 --code    # 주인공 도트 뽑기
node tools/lint-sprites.js                  # 도트 규칙 검사
node tools/shot.js                          # 도트 확인판을 PNG 로
node tools/build.js                         # 한 파일 HTML 만들기
node tools/png2sprite.js 그림.png --frames=4 # 외부에서 그린 그림 가져오기
```

## 9. 자주 고치는 것

| 고치고 싶은 것 | 위치 |
|---|---|
| 이름 | `js/config.js` 의 `PLAYER_NAME` |
| 점프 높이 · 중력 · 걷는 속도 | `js/config.js` 의 `PHYS` |
| 걷기 빠르기 | `js/sprites/player.js` 의 `walkT / 40` (숫자를 키우면 느려짐) |
| 걷기 흔들림 | 같은 파일의 `bounce = 1` (0 으로 하면 흔들림 없음) |
| 캐릭터 색 | `js/sprites/palette.js` |
| 스테이지 지형 | `js/levels.js` (글자 지도) |
| 캐릭터 그림 자체 | `tools/nayul-gen.js` 를 고치고 다시 뽑기, 또는 편집기에서 직접 찍기 |

## 10. 알아 둘 것

- 네이버 블로그·레딧은 이 작업 환경에서 **차단**되어 링크로는 못 엽니다.
  참고 자료는 **HTML 파일이나 캡처로 전달**해야 읽을 수 있습니다.
- 사진 원본은 저장소에 넣지 않았습니다. 색을 뽑는 데만 썼습니다.
- 에이전트를 3개로 나눠 병렬 작업을 시도했으나 세션 사용량 한도로 전부 실패했습니다.
  분할 자체는 유효했고(파일이 안 겹치게 나눠 둠) 한도가 풀리면 재시도 가능합니다.
